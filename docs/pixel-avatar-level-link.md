# 像素分身：用户数据 → 人物等级链接方案

> 状态：讨论稿（基于 v7 接入版本）。仅运行时派生，不改旧存储。

## 1. 数据来源与计分（已实现）

- **搜索** `searches[].query` — 权重 2
- **收藏** `favorites`（title/overview/genre/category/genres） — 权重 3
- **推荐点击** `recos`（title/reason/matchedTags/genres） — 权重 1

每条证据去重后，按命中关键词累计到 8 个风格分 `scores[style]`。总分 `totalScore = Σ scores`。

## 2. 两层等级

### 2.1 8 类目倾向级别（已实现）

- `computeTendencyLevels(scores)` → 每个风格 Lv0–Lv5（阈值 0/1/3/6/10/15）。
- 表示用户在该类目的兴趣深度，用于调试/画像，不直接改变外形。

### 2.2 用户总级别（外形：人物大小）

- `overallLevel(scores) = clamp(0,5, floor(totalScore / 5))`。
- 映射到 v7 的 1–10 等级：`v7Level = max(1, overallLevel * 2)`。
- 传入 iframe `?level=`，v7 内置高度公式 `(139+(level-1)*3.35)*.70` 自动缩放人物。

**为什么总分而非单类目最高分**：外形反映整体活跃度，避免只看一部类型就满级；同时 8 类目倾向仍保留给解锁/画像使用。

## 3. 解锁（坐骑/工具/武器）

- 直接复用 v7 内置解锁表（Lv2/5/8/9/10 五项）+ 装备列表。
- 因等级为派生值，解锁也为派生值：等级达到即解锁，数据减少时可回收（prep 阶段接受）。
- 未来可扩展：某类目达到 Lv4（达人）时解锁该类目专属装备（phase 2）。

## 4. 稳定性与单调性

- 等级只增不减的「高水位」暂不实现（保持无存储改动）。若后续需要，新增 `pixelAvatarPrefs.levelHighWater` 并迁移，需单独确认。
- 打平风格时等级仍随总分上升，避免跳变。
- 新用户：totalScore=0 → overallLevel 0 → v7 level 1（基准体型、无解锁），不白屏。

## 5. 可解释性（调试）

MyDataPanel debug 展示：
- totalScore、per-style scores、per-style levels
- overallLevel、映射 v7 level
- 解锁列表、数据来源计数、fallback reason

## 6. 可调参数（仅改常量，不动存储）

- `LEVEL_POINTS_PER_STEP`（当前 5）：每级所需总分。可调为 8/10 以放慢升级。
- `CATEGORY_LEVEL_THRESHOLDS`：8 类目阈值。
- v7 level 映射系数（当前 ×2）：可改为非线性映射。

## 7. 风险与后续

- iframe 隔离：v7 内部等级滑块仅预览，真实等级由 URL 参数注入；用户手动拖动不会回写数据（prep 阶段接受）。
- 若需双向同步（v7 操作回写数据），需 postMessage 协议，留待定稿阶段。
- 高水位持久化与 per-category 解锁为 phase 2，需单独确认兼容性。

## 8. 建议：让升级与用户数据更深度相关

当前计分仅按「来源权重 × 关键词命中」累加，建议在不破坏兼容性的前提下增强相关性：

1. **时间衰减（Recency）**：为每条证据加时间衰减系数 `decay = 0.5 ^ (daysSince / halfLife)`（建议 halfLife=30 天）。长期不活跃用户等级缓慢下降，但设置下限（Lv1）避免归零挫败。需 `at` 时间戳（搜索已有，收藏/推荐需确认是否有时间字段）。

2. **多样性加成**：在总分之外计算 `diversity = 已触及风格数 / 8`，总 XP = `totalScore * (1 + 0.3*diversity)`。鼓励探索多类目，避免只刷单一类型。

3. **边际递减**：同一风格内第 n 条证据权重 `w / sqrt(n)`，防止单一关键词刷分；收藏仍最高但递减。

4. **深度信号**：除搜索/收藏/推荐，接入更强意图信号（若有）：详情页打开、加入清单、分享、AI 对话追问。每种信号独立权重，但统一进 `scores`。

5. **AI 搜索专项**：`scope === "ai_search"` 的搜索可单独加权（用户主动提问比普通搜索意图更强），或按查询长度/追问轮数加权。

6. **活跃连续性（Streak）**：按 `at` 时间戳计算连续活跃天数，streak≥7 天给 +10% XP，但不持久化等级，仅影响派生 XP。

7. **双轴等级**：总级别（外形大小）+ 最高单类目级别（精通）。总级别决定 size，精通决定解锁专属装备。两轴都从同一份 `scores` 派生，无新存储。

8. **高水位（可选）**：若不希望取消收藏导致等级倒退，引入 `levelHighWater` 存入 `pixelAvatarPrefs`（新增字段，需迁移确认）。prep 阶段暂不实现，先观察用户反馈。

9. **可解释性升级**：debug 面板增加「XP 明细」：每条证据的原始分、衰减后分、多样性系数、最终 XP，让用户看到等级从何而来。

建议实施顺序：先做 1+2+3（纯函数，不改存储），再视数据字段可用性做 4+5，最后决定 8。
