> 版本：v1.0（前期理念打磨版，暂不开发）  
> 适用仓库：`E:/Desktop/kims_video/1.4- Intelligence`  
> 目标文件：`src/components/MyDataPanel.jsx`（新增子组件 `PixelAvatar.jsx`）  
> 状态：待用户确认后再正式开发

---

## 1. 项目概述

### 1.1 目标
将 My Data 区域原有的“存储概览”统计卡片替换为一个**动态像素风人物形象展示界面**，人物与背景均根据用户的“我的收藏”与“我的推荐”历史生成，支持性别切换与“换一换”重新生成，所有人物特征、配饰与背景均为预制资产，互不遮挡，并匹配对应电影/电视剧风格。

### 1.2 替换位置与范围
- 渲染位置：`MyDataPanel` 实际由 `NewSplash.jsx`（开屏页）在底部渲染，非 `NewHomePage`。
- 像素分身区域成为 **My Data 区域最上方** 的主要展示内容。
- **不删除**原有存储概览四个卡片（收藏数/推荐数/存储占用/持久化状态），尤其“持久化状态”与“存储占用”对用户数据管理至关重要，保留在像素分身下方或相邻位置，不丢失任何数据管理能力。

### 1.3 核心约束
- 所有资产预制，无外部图片依赖，inline SVG 即可。
- 人物部件与背景部件相互之间**不遮挡、不重叠**。
- 风格必须与用户喜好的电影/电视剧风格匹配，不能随机稀释个性。
- 无历史数据时给默认“探索者”形象，不留空白、不报错。

## 2. 数据驱动与风格识别（核心数据问题）

### 2.1 不可简单对推荐标签计数
推荐历史不等于真实偏好。系统推荐 10 部科幻片，用户只收藏其中 1 部，若直接统计推荐结果会把科幻过度加权。

### 2.2 三层权重方案

| 数据来源 | 建议权重 | 解释 |
|---|---|---|
| 用户收藏（favorites） | 5 | 最明确的主动偏好信号 |
| 用户主动发起的推荐主题 | 3 | 有一定偏好信号，但次于收藏 |
| 推荐结果中的影片标签 | 1 | 仅代表系统推荐，不代表用户喜欢 |

### 2.3 去重与匹配规则
1. **去重**：同一部影片可能在多个推荐记录中重复出现，统计前必须去重（按 `id` / `tmdbId` / `mbid` / 标题+年份），避免重复推荐放大某种风格权重。
2. **收藏匹配优先**：收藏记录本身无 `genre` 字段，**不建议单纯用标题关键词猜测**。优先将收藏影片与已有推荐记录匹配，沿用推荐记录中的风格标签。
3. **标题关键词仅作低权重补充**：仅当收藏影片无法匹配到任何推荐记录时，再用标题关键词作为低权重补充。
4. **无法识别的影片不参与风格统计**：不强行猜测，不污染风格池。

### 2.4 输出
- **主导风格**：按加权得分取 Top-1～Top-3，决定背景主题与配色基调。
- **偏好标签池**：主导风格标签 + 历史标签 + 锁定标签，用于随机组合抽取。

## 3. 标签体系与随机组合

### 3.1 分层抽取（替代“全局标签池直接混入”）
原方案“主导风格标签 ∪ 用户历史标签 ∪ 全局微标签池”会稀释用户风格。改为：

| 来源 | 占比 | 内容 | 作用 |
|---|---|---|---|
| 用户偏好池 | 70% | 主导风格标签 + 历史标签 | 保证个性化 |
| 相邻风格池 | 20% | 与主导风格相近的标签（如科幻→赛博朋克、机甲、太空探索） | 适度扩展，不突兀 |
| 惊喜探索池 | 10% | 全局微标签池 | 增加随机趣味 |

比例为初始设计，可根据用户体验后续调整。

### 3.2 标签到资产槽位的映射
标签不一定一对一对应一个部件，而是映射到**资产槽位**（多对多）。例如：

| 标签 | 对应槽位示例 |
|---|---|
| 赛博朋克 | 服装、眼镜、背景 |
| 太空探索 | 头盔、服装、背景 |
| 侦探 | 帽子、放大镜、服装 |
| 魔法 | 帽子、法袍、魔杖 |

建立 `标签 → 槽位集合` 映射表，换一换时按槽位从命中的标签池中抽取对应部件。

### 3.3 标签锁定
- 用户可点击标签切换锁定/解锁。
- 换一换时**保留锁定标签**，仅对未锁定标签重新随机。
- 锁定状态跨页面刷新保留（写入 `personalStore.setMeta`）。

### 3.4 标签数量
对应不同用户喜好的标签数量应足够多（建议全系 100+ 微标签，每个风格 12–15 个），且允许随机组合。

## 4. 视觉与资产规范

### 4.1 统一人物骨架（强制）
为避免后期资产错位，所有部件必须遵守同一套坐标规范：

- 所有部件使用相同 `viewBox="0 0 120 120"`。
- 所有头部使用同一个中心点。
- 所有身体使用相同肩宽。
- 腰线、手臂连接点、腿部起点统一。
- 各部件严格限制在自己的绘制区域内（如头发只画头顶，服装只画躯干），组合时直接叠层，不做动态布局。

### 4.2 SVG 分层顺序（从下到上）
1. 背景装饰（独立容器）
2. 后置配饰（背包、披风）
3. 腿部与下装
4. 身体与躯干
5. 上装与袖子
6. 手臂与手部（根据具体服装拆分前臂/后臂）
7. 脸部与五官
8. 头发
9. 前置配饰（眼镜、帽檐等）

### 4.3 主题配色
SVG 内部使用 CSS 自定义变量，而非仅依赖 `currentColor`（`currentColor` 只会继承当前 CSS color，无法让不同主题的多个部件分别获得合适配色）：

```css
.avatar {
  --skin: #f0c49a;
  --hair: #302438;
  --primary: #00ffff;
  --secondary: #ff00ff;
  --outline: #000000;
}
```

轮廓始终保持黑色（`--outline`），保留像素感。

### 4.4 外观（非性别判断）
提供三种外观：**男性外观 / 女性外观 / 中性外观**，避免让用户感觉系统在判断自己的性别。切换控件为小型按钮，置于“换一换”旁边，非最显眼交互。

## 5. 背景与风格匹配

8 种风格背景（沿用 `discoverGenre.js` 分类）：科幻、悬疑、恐怖、动画、战争、犯罪、剧情、奇幻。

每个风格一个 CSS 像素背景（`repeating-linear-gradient` 构造 4×4 像素块）+ 2–3 个动态装饰元素（CSS 动画无限循环）。背景按主导风格显示；无历史时随机一个主题，并提示“开始收藏，让分身穿上你喜爱的电影风格”。

---

## 6. 轻量成长体系（可选，P2）

让用户直观感受到在系统中的积累：

| 指标 | 含义 |
|---|---|
| 收藏数量 | 决定探索等级 |
| 发现过的风格数量 | 决定风格图鉴进度 |
| 历史标签数量 | 决定可用的微标签数量 |

**原则**：不能为了让用户升级而诱导其收藏自己不喜欢的影片。成长体系应奖励真实探索，不制造虚假使用量。

## 8. 技术规范（正式交付前必须满足）

| 项目 | 具体要求 |
|---|---|
| 资产兼容 | 每个部件声明适用槽位、风格和外观类型 |
| 随机算法 | 采用确定性 seed；相同 seed + 相同偏好，必须得到相同结果；不使用 `Math.random()` |
| 锁定标签 | 锁定状态跨页面刷新保留 |
| 历史分析 | 数据变化后重新计算，不要每次渲染都扫描 IndexedDB |
| 存储失败 | 不影响主页渲染，使用默认角色 |
| 性能 | 避免大量 SVG 字符串重复解析 |
| 动画 | 支持 `prefers-reduced-motion` |
| 可访问性 | 按钮有明确的无障碍名称，标签锁定状态可识别（`aria-pressed`） |
| 国际化 | 所有用户可见文案均通过 `i18n.jsx`（zh/en） |

## 9. 风险与降级

- **IndexedDB 禁用/隐私模式**：`personalStore` 已 no-op 设计，本组件统一 catch 为空数组，显示默认随机形象，不影响主页。
- **无历史数据**：显示“探索者”默认形象 + 引导文案，不留空白。
- **资产体积膨胀**：先上线 P0 最小资产集，后续只追加 SVG 字符串，逻辑不变。
